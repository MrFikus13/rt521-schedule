# Как обновлять расписание

Источник данных приложения — [`data/schedule.json`](data/schedule.json) в этом репозитории.
Никаких серверов и баз данных: изменение файла в GitHub — это и есть публикация обновления.

## Быстрый сценарий

1. Откройте `data/schedule.json` в GitHub → **Edit**.
2. Внесите изменение (замена, отмена, дополнительная пара или работа).
3. Поставьте актуальный `updated_at`, например `2026-12-02T18:00:00+03:00`.
4. Нажмите **Commit changes**.
5. GitHub Action `Validate schedule JSON` проверит файл.
6. Приложение подтянет изменения в 18:00 или 20:30 (или сразу по кнопке ⟳).

## Замены и отмены

`changes` — массив объектов:

```json
{
  "date": "2026-12-02",
  "kind": "replace",
  "time": "12:15-13:55",
  "subject": "Практикум по телекоммуникациям",
  "room": "123",
  "teachers": ["Колосовская Е.А."],
  "note": "Практика вместо лекции"
}
```

Допустимые `kind`:

| kind | Что делает |
|---|---|
| `replace` | Удаляет базовую пару на это время и показывает новую |
| `cancel` | Помечает пару отменённой (остаётся в списке, но зачёркнута) |
| `extra` | Добавляет дополнительную пару |

Время всегда в формате `ЧЧ:ММ-ЧЧ:ММ`, дата — `ГГГГ-ММ-ДД`.

## Работы

```json
{
  "date": "2026-12-04",
  "subject": "Теория электрической связи",
  "type": "Контрольная работа",
  "title": "Спектры сигналов",
  "note": "Повторить модуляцию"
}
```

Предмет должен совпадать с названием в расписании (без учёта регистра и ё/е).

## Локальная проверка

```bash
python3 scripts/validate_schedule.py data/schedule.json
```

Скрипт проверяет обязательные поля, дни, формат времени, недели, замены и работы.
Ошибки выводятся с точным путём до поля.

## Настройка репозитория

1. Создайте публичный репозиторий `rt521-schedule`.
2. Загрузите этот проект в ветку `main`.
3. GitHub Actions при сборке сам подставит URL из `github.repository`. Для локальной
   сборки замените `OWNER` в `gradle.properties` или укажите URL в настройках приложения.
4. Запустите GitHub Actions → **Android CI**. Он соберёт debug APK.
5. Для подписанных релизов добавьте secrets `KEYSTORE_BASE64`, `KEYSTORE_PASSWORD`,
   `KEY_ALIAS`, `KEY_PASSWORD` и создайте тег `v2.0.0`.

## Заявки от группы

В репозитории есть issue-шаблон «Замена / работа». Одногруппники могут оставить заявку,
а староста перенесёт её в JSON. Приложение обновится само.
